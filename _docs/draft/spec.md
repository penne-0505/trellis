# Trellis — 要件仕様書

## 1. 概要

主観的な要因と客観的な要因の因果関係を見出すための、Android用ライフログアプリ。

### 前提条件
- ユーザーはHealth Connect対応のウェアラブルデバイスを所持していること（MVPではウェアラブルなしは非サポート）
- 初回セットアップで気象データ取得地点とHealth Connect接続が完了していること

---

## 2. 機能要件

### 2.1 気分記録（MVP必須）
**概要:** Good/Badの2値で気分を記録する。

**受け入れ基準（AC-1）:**
- アプリ内から起動を0として**最大2操作**で記録可能
- ホームウィジェットから記録可能
- 入力元（widget/app_home）を記録に含める
- 記録と同時にフォアグラウンドで位置情報を取得し、成功時は紐付け、失敗時も入力はブロックしない

### 2.2 テキストログ（MVP必須）
**概要:** 自由記述のテキストを記録する。

**受け入れ基準（AC-2）:**
- アプリ内から起動を0として**最大2操作**で入力画面に到達し記録可能
- ウィジェットからの入力はMVPでは不要
- 記録と同時に気分記録と同様の位置情報キャプチャを行う

### 2.3 気象データ同期（MVP必須）
**概要:** Open-Meteo APIを使用し、気象データを定期取得する。

**受け入れ基準（AC-3）:**
- WorkManagerにより1時間ごとに自動取得（天気・気温・気圧・湿度）
- アプリ起動時に欠損チェックを行い、`past_days`パラメータで補填
- ユーザー入力との紐付けはタイムスタンプ近傍結合（外部キーなし）

### 2.4 Health Connect連携（MVP必須）
**概要:** ウェアラブルデータを取得し、以下を保存する：
- 睡眠データ（セッション・ステージ詳細）
- 歩数・心拍（日次サマリ + 1時間粒度詳細）

**受け入れ基準（AC-4）:**
- WorkManagerにより定期同期
- アプリ起動時に欠損チェック・補填
- 1日1回アプリ起動で前日までのデータが揃う状態を保証

### 2.5 位置情報キャプチャ（MVP必須）
**概要:** ユーザー入力時にのみフォアグラウンドで位置を取得する。

**制約:**
- バックグラウンド定期取得はMVPでは行わない
- 失敗時はnull許容し、入力自体は継続

---

## 3. 非機能要件・制約

### 3.1 パーミッションポリシー
- 位置情報：`ACCESS_FINE_LOCATION`または`ACCESS_COARSE_LOCATION`（フォアグラウンドのみ）
- `ACCESS_BACKGROUND_LOCATION`はMVPでは要求しない（Google Play審査ハードルを回避）

### 3.2 データ戦略
- 気象データ：定期取得のみ。入力時スナップショットは作成しない。
- 生体データ：日次サマリ（活用）と1時間粒度（将来のため蓄積）の両方を保存
- 睡眠データ：`BiometricSummaries`から分離し専用テーブルで管理

### 3.3 スコープ除外（MVPでは対象外）
- 感情分析・Embedding機能（テキスト解析）
- 花粉情報の取得
- バックグラウンド位置追跡
- ウィジェットからのテキスト入力
- 履歴画面のフィルタ・検索機能

---

## 4. データ整合性要件

**受け入れ基準（AC-5）:**
- 各テーブルにレコードが期待通り存在し、外部キー整合性が保たれている
- データ蓄積状況をアプリ内で最低限確認可能（ホーム画面タイムラインで代替）
